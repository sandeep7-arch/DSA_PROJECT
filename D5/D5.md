# D5 — Decreases break the prefix-maximum Fenwick rule

The increase-only rule updates every Fenwick cell containing position `i` with `cell = max(cell, newValue)`. This is correct when a value only increases: each affected cell's maximum either stays the same or becomes the new value.

It cannot process decreases. For values `[9,4]`, the first prefix maximum is 9. If position 0 is assigned 1, applying `max(9,1)` leaves the stored prefix as 9, which is wrong. The cell does not remember whether another position also attained its old maximum, so it cannot determine the replacement maximum locally.

A simple correct baseline is to rebuild the prefix Fenwick structure from all `n` values after every decrease. This costs `O(n log n)` with repeated point insertion (or can be made `O(n)` with a dedicated build). An adversarial sequence assigns each current maximum a smaller value repeatedly; every update forces such a rebuild. This establishes why the baseline is unsuitable for frequent decreases, not a lower bound for every possible Fenwick design.
